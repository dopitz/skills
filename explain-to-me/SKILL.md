---
name: explain-to-me
description: explain code or concepts
---

Explain the referenced code, change, or implementation decision at a junior developer level in simple terms. Assume I can read and understand code, but may not know all architectural context, conventions, or reasoning behind the change.

* Answer the actual question directly.
* Ground the answer in the code and current change.
* Explain *why* something exists or was done, not basic programming concepts.
* Point out missing context or incorrect assumptions clearly.
* If something is actually redundant or unnecessary, say so.
* Distinguish technical requirements from design choices.

## Length

* `short` — 2–3 sentences **(default)**
* `mid` — 4–6 sentences
* `long` — 7+ sentences
